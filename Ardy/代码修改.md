# ARDY → SONIC 接入修改说明

这三个文件分别负责：本地文本模型加载、ARDY 动作格式转换，以及仿真场景选择。

## 1. llm2vec.py：加载本地文本编码模型

文件位置：

`ardy/ardy/model/llm2vec/llm2vec.py`

### 作用

LLM2Vec 将自然语言 prompt 转换成文本向量，作为 ARDY 生成动作的条件。

例如：

```text
"A person walks in a circle."
    → 文本向量
    → ARDY 生成转圈动作
```

### 修改内容

下载的 MNTP checkpoint 包含 adapter 权重，并不是完整的 Llama 模型。原代码直接将该目录传给 Transformers，依赖自动识别；当目录同时包含 `config.json` 时，可能无法正确加载。

我们在 `from_pretrained()` 中增加了明确的加载逻辑：

1. 检查本地目录是否存在 `adapter_config.json`。
2. 读取其中的 `base_model_name_or_path`，找到 Llama 底座模型。
3. 如果该路径不是绝对路径，且设置了 `TEXT_ENCODERS_DIR`，则在该目录下查找底座模型。
4. 先加载底座模型，再加载并合并 MNTP adapter。
5. 随后继续通过原有逻辑加载 supervised adapter。

加载顺序：

```text
本地 Llama 底座
    → 加载并合并 MNTP adapter
    → 加载 supervised adapter
    → 生成文本向量
```

### 效果

支持正确加载已经下载到本地的文本编码模型。

完全离线运行还需要：

- 本地模型文件完整。
- adapter 配置指向正确的本地模型路径。
- 配合 `TEXT_ENCODERS_DIR`、`TEXT_ENCODER_MODE=local`、`HF_HUB_OFFLINE=1` 和 `TRANSFORMERS_OFFLINE=1` 等环境设置。

这项修改没有改变文本编码算法，也没有添加 MUSA 算子适配。

## 2. convert_ardy.py：转换 ARDY 动作为 SONIC 参考动作

文件位置：

`GR00T-WholeBodyControl/gear_sonic_deploy/reference/convert_ardy.py`

这是我们新增的脚本，目前在 Git 中仍是未跟踪文件。

### 作用

ARDY 生成的 `.npz` 与 SONIC 所需的参考动作格式不同。该脚本负责完成数据转换。

### 转换过程

#### 第一步：读取 ARDY G1 动作

读取 `.npz` 中的：

- 帧率 `fps`。
- 根节点位置 `root_positions`。
- 局部旋转矩阵 `local_rot_mats`。
- 可选的文字描述 `text`。

脚本针对 ARDY G1 的 34 节点骨架。

如果存在同名 `.csv`，优先读取其中的 MuJoCo `qpos`；也可以通过 `--qpos-csv` 指定文件。

如果没有 `.csv`，则调用 ARDY 官方的 `MujocoQposConverter(G1Skeleton34())`，从 `.npz` 计算 `qpos`。

每帧的 `qpos` 包含：

```text
根节点位置 3 维
+ 根节点四元数 4 维
+ 身体关节角 29 维
= 36 维
```

#### 第二步：统一到 50 FPS

根据输入文件的实际帧率，将动作重采样到 SONIC 使用的 50 FPS。

- 根节点位置和关节角：线性插值。
- 根节点四元数：SLERP 插值。

ARDY G1 通常输出 25 FPS，因此通常需要从 25 FPS 转为 50 FPS。

#### 第三步：对齐关节顺序

读取 ARDY G1 模型的关节名称，以及 SONIC 的 `mujoco_to_isaaclab` 映射。

先通过关节名称匹配，再将 29 个身体关节的数据排列成 SONIC 所需的 IsaacLab 顺序。

#### 第四步：计算身体位置、朝向和速度

使用 SONIC 的 G1 MuJoCo 模型逐帧计算正向运动学，得到选定的 14 个身体节点的世界坐标位置和四元数。

随后计算：

- 关节速度。
- 身体节点线速度。
- 身体节点角速度。

#### 第五步：写出 SONIC 参考动作

复用仓库已有的 `convert_single_motion()`，生成以下文件：

```text
joint_pos.csv
joint_vel.csv
body_pos.csv
body_quat.csv
body_lin_vel.csv
body_ang_vel.csv
metadata.txt
info.txt
```

### 使用示例

在 `GR00T-WholeBodyControl` 仓库根目录执行：

```bash
python gear_sonic_deploy/reference/convert_ardy.py \
  ../ardy/outputs/baseline_walk_circle.npz \
  --output-dir gear_sonic_deploy/reference/ardy/walk_circle
```

上述命令假设两个仓库位于同一个父目录下，且输入动作文件已经存在。

### 效果

将 ARDY G1 动作转换成 SONIC 控制器可以读取的参考动作。

转换在 CPU 上完成，不需要运行 ARDY 模型或 SONIC 策略推理。脚本没有修改控制策略，也没有实现手指控制或抓取。

## 3. run_sim_loop.py：支持选择仿真场景

文件位置：

`GR00T-WholeBodyControl/gear_sonic/scripts/run_sim_loop.py`

### 作用

运行 MuJoCo 仿真，提供机器人状态，并通过 DDS 接收控制器发送的电机命令。

### 修改内容

在加载配置后增加了两行：

```python
if config.scene_path is not None:
    wbc_config["ROBOT_SCENE"] = config.scene_path
```

作用是：如果启动时指定了场景，就用该场景覆盖 YAML 中的默认场景。

配套修改位于：

`gear_sonic/utils/mujoco_sim/configs.py`

其中增加了 `scene_path` 参数，使命令行支持 `--scene-path`。

### 使用示例

在 `GR00T-WholeBodyControl` 仓库根目录执行：

```bash
python gear_sonic/scripts/run_sim_loop.py \
  --interface lo \
  --scene-path gear_sonic/data/robot_model/model_data/g1/scene_43dof_blocks.xml
```

场景路径可以是绝对路径，也可以是相对于当前工作目录的路径。没有指定 `--scene-path` 时，继续使用 YAML 中的默认场景。

如果要显示图形窗口，还需要可用的显示环境。

### 效果

可以在启动时选择已经准备好的木块场景，无须反复修改默认 YAML。

原有的仿真和控制通信逻辑没有改变。这个文件本身不读取 ARDY 动作，也不执行 SONIC 策略。

## 4. 三个文件在整体流程中的关系

```text
文字 prompt
    ↓
llm2vec.py
加载本地文本模型，生成文本向量
    ↓
ARDY
生成 G1 动作 .npz / .csv
    ↓
convert_ardy.py
转换为 SONIC 参考动作文件
    ↓
g1_deploy_onnx_ref
读取参考动作，执行 SONIC 控制策略
    ↕ DDS
run_sim_loop.py
运行 MuJoCo 场景，接收电机命令并反馈机器人状态
```

目前这些修改实现了本地模型加载、动作格式接入和仿真场景选择，尚未实现物体感知、手指闭合或自主抓取。
