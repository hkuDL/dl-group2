## 二、第二段纪要（10:38 起）

**概览**：会议围绕机器人抓取任务展开，明确了基础任务流程与模型部署方案，探讨了外挂大模型、语音交互等拓展方向，并落实了项目分工与评分机制。

**要点**

**1. 技术方案与拓展方向探讨**

- **基础任务与模型部署**
  - 核心任务明确：项目要求机器人根据文字指令，在仿真环境中抓取并抬起桌上的方块，对比不同动作生成方法在相同条件下的表现。
  - 无需自采数据：基础任务直接采用零样本部署，无需自行采集训练数据，重点在于跑通基础推理流程。
  - 底层控制器适配：不同模型输出的动作格式可能存在差异，后续均需接入 Sonic 底层控制器进行适配处理。
- **拓展方向评估**
  - 外挂大模型方案：引入云端大模型作为大脑指挥端侧 VLA 模型，可提升交互性，但需确认是否有免费或报销的 API 额度支持。
  - 语音交互功能：建议在系统中外挂语音识别模型，实现与机器人的实时语音对话，提升交互体验。
  - 仿真环境泛化能力：针对真机环境泛化差的问题，建议在仿真环境中加入位置泛化测试，主流算法在仿真环境中具备较好的空间位置泛化能力。
  - 强化学习应用：当前项目以部署为主，离线强化学习虽有效但在此项目中可能无用武之地，建议暂不考虑。

**2. 项目执行与分工规划**

- **算力资源评估**：目前仅有 1–2 张 H100 显卡可用，若自行训练小模型可能面临资源不足或效果不佳的风险。
- **团队分工与协作**
  - 并行推进任务：建议有部署经验的同学优先跑通主流程，其他同学并行准备数据采集与格式处理等 Bonus 工作。
  - 统一最终呈现：项目最终汇报需团队协作完成，建议两组各出一人负责实际功能演示，确保整体效果统一。

**3. 评分与 Bonus 机制**

- **基础评分规则**：基础分分配相对平均，只要积极参与并完成任务，最终得分将由团队统一意见决定，整体分配相对平均。

## 三、重点提炼

**1. 任务边界已经定死，不要过度设计**

主线是：机器人在仿真环境里按文字指令抓取并抬起方块，对比不同动作生成方法在同一条件下的表现。基础任务走零样本部署，不用自己采数据、不用自己训模型、也不要求在真机上跑自训练模型。所有模型输出最终都要接 Sonic 底层控制器做适配。

**2. 模型选型上有两个关键判断**

- 官方给四个候选模型，Key Model 偏高精度完整动作，ARDY 支持实时文本交互修正。
- 建宇提出的反常识规律值得记一下：越复杂的模型在真机上效果可能越差，建议先用简单模型把成功率做上去，汇报内容再另想办法包装。

**3. 算力是这轮最实际的卡点**

可用 H100 只有 1–2 张，自训小模型风险高、收益低。另外昇腾 910C 只支持 NPU 训练、不支持图形渲染推理，用了会直接影响部署；虽然用国产卡有 Bonus，但基础设施适配经验不足，纪要建议视情况放弃这一项加分。

**4. 拓展方向的优先级**

外挂云端大模型当"大脑"指挥端侧 VLA、外挂语音识别做实时对话，都是加分项而非主线；外挂大模型还要先确认有没有免费或可报销的 API 额度。仿真侧建议补位置泛化测试来缓解真机泛化差的问题。离线强化学习在这个项目里用不上，暂不考虑。

**5. 分工思路尚未定稿**

李静瑶给了两套方案：四组并行（环境部署 / 两个模型各一组 / 对比与报告）或按模型分两组。这件事要群内投票决定，还没落。已明确的原则是"先把最小可用产品跑通，再考虑加分项"，有部署经验的人先跑主流程，其他人并行准备数据采集与格式处理。
